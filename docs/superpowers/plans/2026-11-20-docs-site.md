# Docs site (stage 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local docs site for dograpper, built with one command. Each command
page has the README's prose, an options reference generated from the click
tree, and an "Options in detail" section. A pytest guard keeps the site's
flags in step with the CLI.

**Architecture:** Sphinx reads the Markdown pages in `site/` through MyST, and
the `dograpper-options` directive (defined in `site/conf.py`, reusing
`option_cells()` from `src/dograpper/commands/docs.py`) renders each command's
options from the click objects. Furo is the theme. The README stays unchanged: pages are copies of its text
until a later cutover. `CHANGELOG.md` and `docs/schema-v1.md` are not copied;
their pages include them. `tests/test_docs_site.py` parses the Markdown only,
so CI needs neither Sphinx nor the `docs` extra.

**Tech Stack:** Sphinx, myst-parser, furo (new `docs` optional extra); pytest and click for the guard.

**Spec:** `docs/superpowers/specs/2026-11-20-docs-site-design.md`

> **Revision (Task 3).** sphinx-click is out (see the spec's Revision). Options
> come from ```` ```{dograpper-options} <command> ```` (or `dograpper` for the
> root), a directive in `site/conf.py` built on `option_cells()` from
> `src/dograpper/commands/docs.py`. The guard checks that directive. Tasks 1–3
> below keep their original text as executed; Tasks 4–7 are updated.

## Global Constraints

- Build command, exactly:
  `uv run --extra docs sphinx-build -W --keep-going -b html site site/_build/html`.
  It must exit 0 with no warnings.
- The docs tooling lives only in `[project.optional-dependencies] docs` in
  `pyproject.toml`, never in runtime dependencies. These floors resolve on both
  Python 3.10 and 3.12:
  - `sphinx>=8.1`
  - `myst-parser>=4.0`
  - `furo>=2025.12`
  - (`sphinx-click>=6.2` dropped in Task 3, see Revision)
- No Node.js toolchain.
- All site text is in English.
- `README.md` is not modified. In `CHANGELOG.md` and `docs/schema-v1.md`, the
  only change allowed is rewriting relative links to
  `https://github.com/lorenzoervedosa/dograpper/blob/main/<path>`.
- Copy wording verbatim from the README. The only edits allowed:
  - heading levels shift: `### dograpper X` becomes `#`, and `####` becomes
    `##`;
  - option tables are removed;
  - a table cell's text moves into an "Options in detail" paragraph;
  - links are rewritten (see the next item).
- Links:
  - A README `(#anchor)` whose section is already on the site becomes
    `(<relative-page>.md#anchor)`.
  - One whose section is not on the site yet becomes
    `(https://github.com/lorenzoervedosa/dograpper/blob/main/README.md#anchor)`.
    Task 7 removes these.
- No hand-written option table on the site.
- Nothing from `docs/adr/`, `DEBT.md`, `DECISIONS.md`, `superpowers/`,
  `audits/`, `discovery/`, `glossario.md` or `migration-v0.1-v0.2.md` lands
  under `site/`.
- The section title "Downloader profiles" is kept: CLI messages and tests name
  it.
- `dograpper docs` and `.github/workflows/` are not touched.
- Every commit passes `uv run pytest tests/ -q` (contract 5). Commits use
  `docs(site):` or `test(site):`, and none of them earns a CHANGELOG entry.

## Review Focus

- **A copied page keeps a README `#anchor` that now lives on another page.**
  The build must fail rather than ship a dead link. The `-W` build in each
  content task's verification step catches it.
- **A page cites another tool's flag** (wget `--mirror`, uv `--extra`). The
  guard must accept a flag listed in `FOREIGN_FLAGS` and name any other
  unknown flag with its page. Covered by `test_flags_in` and
  `test_every_flag_on_the_site_exists` (Task 2).
- **A future CHANGELOG entry adds a relative `docs/adr/...` link.** CI must
  fail before the local build does. Covered by
  `test_included_docs_have_no_relative_links` (Tasks 6 and 7).
- **A new click command lands without a page.** CI must fail. Covered by
  `test_every_command_has_a_page` (Task 5).
- **The maintainer builds on Python 3.10**, where Sphinx resolves to 8.1, not
  9.x. The build must still pass. Task 1, Step 3 runs it there.

### Task 2: Drift guard

**Files:**
- Create: `tests/test_docs_site.py`
- Modify: `tests/CLAUDE.md` (tree entry; `test_claude_md_inventory.py` requires
  it)

**Interfaces:**
- Consumes: `dograpper.cli.cli` (a `click.Group`) and `site/**/*.md`.
- Produces these module-level helpers in `tests/test_docs_site.py`, which
  Tasks 5–7 extend:
  - `SITE = REPO_ROOT / "site"`
  - `FOREIGN_FLAGS: frozenset[str]`, holding flags of other tools the docs cite:
    - wget: `--mirror`, `--no-parent`, `--convert-links`,
      `--adjust-extension`, `--page-requisites`, `--timestamping`,
      `--continue`, `--accept-regex`, `--reject-regex`;
    - HTTrack: `--update`;
    - uv: `--extra`;
    - Claude Code: `--add-dir`;
    - git: `--cached`.
  - `_flags_in(text: str) -> set[str]`, using the regex
    `(?<![\w-])--[a-z][a-z0-9-]*`.
  - `_option_flags(cmd: click.Command, ctx: click.Context) -> set[str]`: every
    `--` name in `opts + secondary_opts` of `cmd.get_params(ctx)`, which
    includes `--help` (and `--version` on the root).
  - `_cli_flags() -> set[str]`: the root plus every command.
  - `_site_pages() -> list[Path]`: `site/**/*.md`, skipping `site/_build/`.
  - `_command_pages() -> dict[str, Path]`: the stem of each file in
    `site/commands/*.md`, mapped to its path.
  - Directive parsing:
    - the target comes from ```` ```{click} <module>:<attr> ```` or the
      fallback `.. click:: <module>:<attr>`;
    - the prog comes from the `:prog: <value>` line.
  - Detail headings come from `^### `?(--[a-z][a-z0-9-]*)`.

- [ ] **Step 1: Write the failing tests.**
  - `test_flags_in`, parametrized:

    | input | expected |
    |---|---|
    | ``"see `--depth` and --no-report"`` | `{"--depth", "--no-report"}` |
    | `"\|---\|---\|"` | `set()` |
    | `"a — b -- c"` | `set()` |
    | ``"`-o` only"`` | `set()` |

  - `test_every_command_page_names_a_command`: each `_command_pages()` stem is
    in `cli.commands`.
  - `test_every_command_page_renders_its_own_command`:
    - each command page has exactly one directive;
    - its target resolves, via `importlib`, to the very object
      `cli.commands[stem]`;
    - its prog is `f"dograpper {stem}"`.
  - `test_detail_headings_are_options_of_their_command`:
    - on each command page, the detail headings are a subset of
      `_option_flags` of that command;
    - on `site/reference/global-options.md`, when it exists, a subset of the
      root's flags.
  - `test_every_flag_on_the_site_exists`: the set of `(page, flag)` pairs with
    a flag not in `_cli_flags() | FOREIGN_FLAGS` is empty. The assert message
    lists the pairs.
- [ ] **Step 2: Run it.** Run `uv run pytest tests/test_docs_site.py -v`.
  Expected: FAIL, because `_flags_in` is not defined yet.
